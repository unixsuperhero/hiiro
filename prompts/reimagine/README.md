- Shapes. Picker item `Picker::Item{ identity: ["branch", "/src/app", "main"], label, fields: { "name" => "main", "repo" => "/src/app" }, value }`. Identity by family: command `[command, kind, name, source file]`; file `[file, base, path relative to base]` (realpaths, `/` separators, `./` stripped, base `/` outside it); task `[task, id]` (`name:NAME` for the id-less synthetic subtask main); project `[project, name]`; branch `[branch, main-checkout repo, name]` (from `--git-common-dir`, so every worktree shares it); PR `[pr, owner/name, number]`; saved `[saved, store, key]` (link ID, vault-relative note, Portfolio ID, saved file, registry row ID, task resource ID). Exclusion rule (one `picker_exclusions` row, owner `Hiiro::PickerExclusion`): `{ id, picker, scope: picker|task|project|global, scope_key: task id | project name | null, mode: exact|literal|substring|regex|glob|extglob, field, pattern, label (presentation only, exact rules), created_at }`. Edit document (YAML through `InputFile.yaml_file` → `EditedDocument`): `scope:` (default for new rules: `task` when a task is current, else `picker`), `items:` = the snapshot of the rows listed when Ctrl-E was pressed (identity JSON per line; the label is a comment), and `rules:` = the applicable rules as `{id, scope, mode, field, pattern}`.
- Rule semantics. `Document#change` returns `Change{ add, remove }` or raises `Picker::Invalid`. A deleted snapshot row becomes an `exact` rule for that identity. A line that is not in the snapshot is rejected, so filtered, already excluded, and later items can never be excluded by an edit. Deleting a rule line removes the rule; changing it replaces the rule; a line without `id` adds one. Unknown keys, fields, modes, and scopes are rejected, as are an unavailable task or project scope, an unknown id, and a malformed regex (Onigmo, unanchored, 1 s timeout) or glob/extglob (`Hiiro::PathPattern`, a Ruby backtracking matcher). Glob semantics: `*` `?` `[...]` within a segment, `**/` for zero or more segments, `**` elsewhere crossing `/`, `\` escape, whole-value match. Extglob adds `?() *() +() @() !()` inside one segment. All modes are case-sensitive (a regex can use `(?i)`), and path values and path patterns are normalized. Applicability: `picker` everywhere for that picker; `task`/`project` only for that picker with the same current task id or project; `global` for every picker whose items carry the field. Global applies only when the document names it, and the preview warns. `TableScope` is not consulted.
